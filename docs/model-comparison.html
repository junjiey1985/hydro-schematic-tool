实验设计

A · 结构误差实验：四个模型用同一套"实测"流量（本平台 HBV 雪版模型以真值参数生成、叠加 5% 观测噪声的 OSSE 数据）各自链式率定。由于"实测"由 HBV 生成，HBV 拟合最好属预期；其余模型与 HBV 的差距即为「模型结构不匹配」的代价量级——这正是换模型前需要预知的信息。

B · 框架自洽性：每个模型改用自己的真值参数生成 OSSE 流量再率定回收。若框架实现正确，各模型都应高 NSE 回收自身真值、参数偏差集中在小幅区间；任何模型回收失败都指向实现 bug 而非数据。

结论

  • 框架自洽性成立：B 部分四个模型都能以高 NSE 回收自身真值（最差单元 0.945~0.995）——多模型注册、链式率定、参数体系按模型隔离的实现是正确的。
  • 但"高 NSE"≠"参数可唯一辨识"：Tank / HBV 参数较多，回收后仍有 80%+ 的参数偏差超过 15%（XAJ / GR4J 约 20%）。这不是实现 bug，而是概念性模型的参数补偿（equifinality）——多组参数给出几乎相同的出口过程线（本平台 P7 的 GLUE 分析正是为此而生）。实践含义：不要逐参数解读率定值；评价模型看过程线指标与验证期表现，参数不确定性用 GLUE 置信带表达。
  • 结构误差量级：A 部分中 HBV（数据生成模型）率定期最差单元 NSE 0.945；其余模型中最优的 新安江三水源 为 0.926，最差的 GR4J 为 0.875。用错模型结构的代价在本演示流域约为 0.02–0.07 的 NSE 差距——换模型前值得先做这类对比，而不是凭文献偏好选型。
  • 成本参考：相同预算（1200 evals/单元）下 GR4J 耗时最长（44 s）却参数最少——其双单位线（UH1/UH2）逐步演算的成本高于简单线性水库；Tank 最快（18 s）。预算敏感场景可选 Tank，机制解释优先选 HBV。
  • 局限：本实验"实测"为合成数据（OSSE），只代表「HBV 能生成的过程」范围内的结构误差；对真实观测（含观测误差与人类活动影响）结论需重新标定。真实流域应用建议：多模型并行率定 → 按验证期指标与过程线形态（洪峰 / 基流 / 峰现时间）选型，或做加权集成。
